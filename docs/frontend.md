# Frontend

The brain site is a React 19 single-page application served by the brain binary at `:12000`.

## Architecture overview

```
main.tsx
  └── ThemeProvider (ThemeContext)
        └── QueryClientProvider (TanStack Query)
              └── RouterProvider (TanStack Router)
                    └── RootLayout
                          ├── TopNav
                          ├── Sidebar
                          └── <route outlet>
                                ├── /           → HomePage
                                ├── /ctx7       → Ctx7Page (lazy)
                                ├── /schema     → SchemaPage (lazy)
                                ├── /api-docs   → ApiDocsPage (lazy)
                                └── $           → DocPage (lazy, catches all other paths)
```

## Routing

**File:** `src/routeTree.ts`

TanStack Router with code-based route definitions. All routes except `HomePage` are lazy-loaded via `React.lazy()` — their JS chunks are not included in the initial bundle and only download when the route is first visited.

The `$` (catch-all) route maps any unrecognized path to `DocPage`, which interprets the path as a doc address (`root/path`). This means navigating to `/brain/notes/foo` opens that vault doc directly.

## State management

There is no global state store (no Redux, no Zustand). State lives in three places:

1. **TanStack Query** — all server state. API responses are cached, background-refreshed, and shared across components via query keys. Cache times differ in dev vs prod (see `main.tsx`).
2. **ThemeContext** (`src/contexts/ThemeContext.tsx`) — color mode (light/dark) and palette selection. Persisted to localStorage.
3. **Local component state** — UI-only state (open/closed, selected item) lives in `useState` in the component that owns it.

## Data fetching pattern

Every API call goes through TanStack Query. The generated hooks in `src/api/` (output of `npm run gen`) provide typed query functions:

```tsx
// Generated hook — do not call fetch() directly
const { data, isLoading } = useGetTree();
```

The `gen` script (`site/scripts/gen.ts`) hits `/api/openapi.json` and produces:
- `src/api/` — typed fetch functions and React Query hooks
- `src/schema/` — TypeScript types matching the OpenAPI schemas

**Never call `fetch()` directly in components.** If a new API endpoint is added, run `npm run gen` to regenerate the hooks.

## Theming

Mantine's theme system + CSS custom properties. `ThemeContext` exposes:
- `mode` — `"light" | "dark"`
- `theme` — named palette (e.g. `"default"`, `"solarized"`)
- `PALETTES` — the full color token map per theme/mode

Components that need to match the theme (like Scalar) read values from `PALETTES[theme][mode]` and apply them as inline CSS custom property overrides.

## Build pipeline

```
npm run build
  └── tsc -b          type check only (noEmit: true)
  └── vite build      compile + bundle → site/dist/
```

Vite 8 uses Rolldown. Manual chunk config splits vendor libs into stable named files for browser caching. Route-level lazy loading splits route code into separate chunks fetched on demand.

The output `site/dist/` is then compiled into the Rust binary by `rust-embed`. See [single-binary.md](single-binary.md).

## Dev workflow

```sh
make dev
```

Starts two processes:
1. `cargo watch` — rebuilds the Rust binary on `src/` changes, restarts `brain serve --dev`
2. `vite` — HMR dev server on `:12001`, proxies `/api/` to `:12000`

In dev mode, the Rust server only handles API routes. Vite handles the frontend with hot module replacement. The site is NOT embedded in the debug binary — only `cargo build --release` embeds the site.

## Generated files

`src/api/` and `src/schema/` are generated by `npm run gen`. Never edit them manually — they will be overwritten on the next `gen` run. The `gen` script runs automatically after each backend restart in `make dev`.

If the backend API changes (new endpoint, changed schema), run:
```sh
cd site && npm run gen
```
