# Frontend Guide

How to make changes to the brain web UI. Covers adding pages, adding API endpoints, and working with the code generation pipeline.

---

## Development setup

```bash
make dev
```

This runs `op run --env-file .env.brain.tpl -- bash scripts/dev.sh`, which starts:
- **cargo-watch** — rebuilds the Rust server on every `.rs` file save, reinstalls to `~/.local/bin/brain`
- **Vite HMR** — serves the frontend on `:12001` with hot module replacement

The Vite config proxies `/api/*` to `:12000` (the Rust server). So in dev you browse to `http://localhost:12001` and all API calls route to Rust automatically.

## Adding a new page

### 1. Create the route file

```tsx
// projects/frontend/src/routes/WidgetsPage.tsx
export function WidgetsPage() {
  return (
    <div>
      <h1>Widgets</h1>
    </div>
  );
}
```

### 2. Register the route

Open `projects/frontend/src/main.tsx` (or wherever the router is configured) and add:

```tsx
import { WidgetsPage } from './routes/WidgetsPage';

const widgetsRoute = createRoute({
  getParentRoute: () => layoutRoute,
  path: '/widgets',
  component: WidgetsPage,
});

// Add widgetsRoute to the routeTree
```

### 3. Add a nav link (optional)

In `projects/frontend/src/components/Sidebar.tsx`, the static nav links live in the `sidebar-nav` block:

```tsx
<div className="sidebar-nav">
  <Link to="/schema"   className="sidebar-nav-link" activeProps={{ className: 'sidebar-nav-link active' }}>Schema</Link>
  <Link to="/api-docs" className="sidebar-nav-link" activeProps={{ className: 'sidebar-nav-link active' }}>API Docs</Link>
  <Link to="/session"  className="sidebar-nav-link" activeProps={{ className: 'sidebar-nav-link active' }}>Session</Link>
  <Link to="/widgets"  className="sidebar-nav-link" activeProps={{ className: 'sidebar-nav-link active' }}>Widgets</Link>
</div>
```

## Adding a new API endpoint (Rust)

### 1. Write the handler

Open `projects/server/src/serve/api.rs` and add a handler function:

```rust
#[utoipa::path(
    get,
    path = "/api/widgets",
    responses((status = 200, description = "List of widgets")),
)]
pub async fn get_widgets() -> impl IntoResponse {
    Json(json!([{ "id": 1, "name": "example" }]))
}
```

The `#[utoipa::path]` attribute auto-generates the OpenAPI spec entry. Always include it so the spec stays in sync.

### 2. Register the route

In `projects/server/src/serve/mod.rs`, add the route to the axum router:

```rust
.route("/api/widgets", get(api::get_widgets))
```

### 3. Rebuild

```bash
make watch   # cargo-watch handles this automatically in dev
```

The server restarts and the new endpoint is live at `http://localhost:12000/api/widgets`.

## Fetching data in the frontend (without codegen)

For quick iteration, you can write a fetch directly:

```tsx
import { useQuery } from '@tanstack/react-query';

function useWidgets() {
  return useQuery({
    queryKey: ['widgets'],
    queryFn: () => fetch('/api/widgets').then(r => r.json()),
  });
}

export function WidgetsPage() {
  const { data, isLoading } = useWidgets();

  if (isLoading) return <p className="muted">Loading…</p>;

  return (
    <ul>
      {data?.map((w: { id: number; name: string }) => (
        <li key={w.id}>{w.name}</li>
      ))}
    </ul>
  );
}
```

## Using the codegen pipeline (typed API client)

For endpoints that will be used long-term, use the generated typed client instead of raw `fetch`.

### How it works

1. The Rust server exposes `/api/openapi.json` — a full OpenAPI 3.1 spec generated by utoipa from the `#[utoipa::path]` annotations
2. `npm run gen` calls that endpoint, runs `openapi-typescript`, and writes typed hooks and types into:
   - `projects/frontend/src/api/` — typed `fetch` functions and `useQuery` hooks
   - `projects/frontend/src/schema/` — TypeScript interfaces matching every response type

### Running codegen

The server must be running first:

```bash
brain serve &    # or make dev in another terminal
cd projects/frontend
npm run gen
```

### Using generated hooks

```tsx
import { useGetWidgets } from '../api/hooks';

export function WidgetsPage() {
  const { data, isLoading } = useGetWidgets();
  // data is fully typed — no manual type annotations needed
}
```

Never edit files in `src/api/` or `src/schema/` directly — they're overwritten on every `npm run gen`.

## Styling conventions

All styles live in `projects/frontend/src/index.css`. New components follow the same pattern:

```css
/* Namespace with the component prefix */
.widgets-page { max-width: 860px; }
.widgets-list { display: flex; flex-direction: column; gap: 0.5rem; }
.widgets-item {
  background: var(--surface);
  border: 1px solid var(--border);
  border-radius: 6px;
  padding: 0.65rem 0.9rem;
}
```

Use CSS variables — `var(--bg)`, `var(--surface)`, `var(--border)`, `var(--text)`, `var(--muted)`, `var(--accent)`, `var(--code-bg)`. These switch automatically with the theme.

Do not use Mantine's `sx` prop or inline styles for anything that should respond to theme changes — use a class with CSS variables instead.

## Adding a doc to the learning system

Drop a `.md` file into `projects/docs/src/` (or a subdirectory like `learn/`):

```
projects/docs/src/learn/my-topic.md
```

It appears in the sidebar under **Brain Docs → learn** after rebuilding the binary. No registration required — `rust-embed` picks up all `.md` files in the directory at compile time.

For it to show up immediately in dev without rebuilding, you can also put it in the brain vault at `~/brain/` — those docs are served live from the filesystem.

## Running tests

```bash
make test        # Vitest (frontend) + cargo test (Rust)
make test-e2e    # Playwright end-to-end tests
```

Frontend unit tests live next to the component: `ComponentName.test.tsx`. Rust unit tests live in the same file as the code under `#[cfg(test)] mod tests { ... }`.

---

## Build for release

```bash
make build
```

This:
1. Runs `npm run build` → generates `projects/frontend/dist/`
2. Runs `cargo build --release` → embeds `dist/` into the binary via rust-embed
3. Outputs `target/release/brain`

```bash
make install    # copies to ~/.local/bin/brain
```

After install, `brain serve` runs the production build with the React app embedded — no Node, no Vite, no separate process.
